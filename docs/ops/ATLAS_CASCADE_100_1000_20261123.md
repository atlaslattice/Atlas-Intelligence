## 100 then 1,000 — actual executed steps

The engine sorts only public issue/PR metadata, round-robins across repositories, and adds one unique required-review stage to one real source-linked backlog item. After each step, the next state depends on the previous item stage and previous global checksum.

|---|---:|---|---|
| Pilot | 100 | `data/atlas_cascade_100_pilot_20261123.json` | `a948570f2487761f` |
| Follow-on | 1,000 | `data/atlas_cascade_1000_expansion_20261123.json` | `b03d9322902e100a` |
| Extra coverage-completion | 220 | `data/atlas_cascade_220_completion_20261123.json` | `32d8fcce0ee6cd28` |

The requested 100 + 1,000 was completed **before** the optional 220-step continuation. The third phase preserves the second phase's end checksum exactly; it does not rewrite or re-label earlier steps. Total candidate review requirements: **1,320 = 440 × 3**.

The three stages for each backlog item are:

1. **PIN_CURRENT_SOURCE** — re-fetch the live GitHub item/PR head; preserve exact source, issue status, timestamp and upstream lineage before acting.
2. **VERIFY_RIGHTS_SCOPE** — check source-owner rights, consent, private Work/Play/Imagine boundaries, revocation and non-harvest requirements. Not a permission-granting function.
3. **PROVE_ACCEPTANCE** — require current-head tests and CI or appropriately scoped document receipts, dissent handling, reviewer decision and rollback before closure or merge.

At the end of the requested 1,100 transitions: 440 source checks, 440 rights checks and 220 acceptance checks have been **proposed**, leaving 220 third-stage review requirements unassigned. The supplemental 220 extends the immutable history to a full three-stage coverage plan. Every request remains `UNVERIFIED_REQUEST_NOT_COMPLETED`; all issue/PR status and actual source rights remain separate evidence questions.

## Reproduction, no external effects

From a checkout of the review branch:

```bash
node --test tests/test_atlas_source_cascade.test.mjs
node scripts/run_atlas_source_cascade.mjs
node scripts/run_atlas_source_cascade.mjs --all-three-gates
```

The runner reads the pinned local GitHub snapshot; default operation **does not write any files**. To intentionally create local replay records, pass `--out-prefix ./my-output/atlas` to a directory that already exists. The runner creates new files with exclusive `wx` flags (no overwrites); it never contacts GitHub, SwarmChat, connected accounts, providers, Play or a model.

It does **not** perform the required individual rights checks, code reviews, model conversations, lab experiments, external outreach, closed-loop autonomous improvements or production tests. Those must remain real actions with separately attributable results.
