## Why 'automatic' still has a concrete host boundary

## Constructively adversarial R2 correction — caller-owned source spoofing

An independent peer source review identified a category of forged catalogue/source-digest admissions. The original v1 `prepareSwarmChatEnvelope` accepted a plain caller-owned four-field `{coordinate,sourceDigest,sourceEdition,suggestedMode}` object and returned `PREPARED_NOT_POSTED`. It never granted host rights, but could be misread as source custody. The R2 patch on the SAME draft keeps history intact and requires an **opaque, frozen in-process Work token** from `bindR07WorkSource(ownerRawPlanBytes, expectedPlanDigest, coordinate)`. That binder invokes the full existing R07 1,728-record validator, selects exactly one WORK record from its bounded original catalogue, and refuses missing/protected records without disclosing their existence or content. Calling `prepareSwarmChatEnvelope` with a forged, spread, cloned or getter-bearing plain object HOLDs. Even a successfully prepared token remains `COMPLETE_R07_CATALOGUE_SHAPE_ONLY`, NOT a host-signed identity or source ownership attestation. The subsequent trusted issuer/READ+RETURN/revocation gate remains outside this module. R2 adds a distinct regression test.
